# Архитектура Aim Trainer

Как устроена программа **сейчас** — Pascal-версия, которая остаётся как
есть и служит эталоном переноса на C++ (D-08, D-09). Что решено и почему —
`docs/direction/DECISIONS.md`; известные отступления кода от
задуманного — находки `AUD-NN` в `docs/audits/PROJECT_AUDIT.md` (ссылки
ниже). Ссылки — на имена процедур и типов, а не на строки: строки
уезжают с каждой правкой.

Документ сверен с кодом коммита `c2ffb35` (13 октября 2026). Правка
кода, которая меняет описанное здесь, меняет и этот документ в том же PR.
Что уже есть в C++-версии — §12.

## 1. Модули

```
AIM_Trainer.pas  (программа)
  uses GraphABC   — окно, рисование, события (поставка PascalABC.NET)
       Base       — IfThen<T>, текст на плашке, кривая Безье
       Control_AI — ввод: события GraphABC → TInputState
       AimCircle  — цель TCircle, TGameMode, THitInfo, TCircleContext
```

| модуль | отвечает за | не делает |
|---|---|---|
| `AIM_Trainer.pas` | экраны и их циклы, игровое состояние `Game`, счёт, статистика и рекорды, профили, файлы, меню и панели, эффекты, звук, темы, достижения | — всё остальное собрано здесь (AUD-24) |
| `AimCircle.pas` | одна цель: появление, движение (Tracking), радиус, отрисовка, попадание, наводка | не читает `Game`: всё нужное приходит в `TCircleContext` |
| `Control_AI.pas` | флаги клавиш и кнопок мыши, позиция курсора | не знает об экранах; `Pressed` мыши гасит потребитель |
| `Base.pas` | общие мелочи рисования | — |

Все модули лежат рядом с программой — в `archive/pascal/` (D-28):
PascalABC.NET ищет модули из `uses` в каталоге программы (D-02).

## 2. Экраны и главный цикл

Главный блок программы инициализирует окно 800×600 (фиксированный
размер, `SetWindowIsFixedSize`), `LockDrawing` (двойная буферизация),
шрифт Consolas, `Randomize`, ввод, темы, достижения, туториал,
загружает профиль 1 (`LoadStats`), режимы (`InitModes`) и крутит
`while True` по `Screen: TScreen`:

```
                 клик по режиму                    3 с
  scMainMenu ─────────────────────► scCountdown ─────────► scGame
      ▲   ▲                            │  ▲                  │ │ │
      │   └──────────── M ─────────────┘  │ R (без сохр.)    │ │ │
      │                                    └──────────────────┘ │ │
      │◄──────────── M (сохранить) ─────────────────────────────┘ │
      │                                                           │ Fail / Esc
      │            Space, M                                       ▼ (сохранить)
      └────────────────────────────────────────────────────── scGameOver
                                         R ──► scCountdown
```

| экран | процедура | что в каждом кадре |
|---|---|---|
| `scMainMenu` | `StartScreen` | частицы, `RenderMainMenu` (внутри — `UpdateMenuInput`), `Redraw`, `Esc` закрывает панели, `UpdateInput`, `LimitFrameRate` |
| `scCountdown` | `CountdownScreen` | 3 → 2 → 1 по `Milliseconds`; на выходе `InitGameState`; `M` — в меню |
| `scGame` | `GameLoop` | `P` пауза, `UpdateGame`, `RenderGame` (+ пауза), `Redraw`, `R`/`M`/`Esc`, проверка `Game.Fail`, `UpdateInput`, `LimitFrameRate` |
| `scGameOver` | `GameOverScreen` | `RenderGameOver` (итоги, тепловая карта промахов); `Space`/`M` — меню, `R` — снова |

Конец игры — `FinishGameAndSaveStats`: итоги, рекорды, таблица лидеров,
строка истории, достижения по итогу, перенос реакций в сохраняемый
буфер, `SaveStats`. Вызывается из `GameLoop` по `Game.Fail` (сюда же
`Esc` и бомба) и по `M`; `R` забег не сохраняет.

## 3. Время

- **Часы игры** — `Game.FrameTime := MillisecondsDelta` в начале
  `UpdateGame`; `Game.TryTime` — сумма кадров с начала забега. От них
  зависят жизнь цели и замер реакции.
- **Абсолютное время** — `Milliseconds`: отсчёт, анимации меню,
  эффекты, уведомления, ограничитель кадров.
- **Сброс дельты** — вызов `MillisecondsDelta` без присваивания перед
  началом `GameLoop` и при снятии паузы: время меню и паузы не попадает в
  первую цель.
- **Ограничитель** `LimitFrameRate`: если кадр короче `MIN_FRAME_MS`
  (`1000 div 240` = 4 мс) — `Sleep` на остаток.

**Зависимость от версии среды (AUD-01).** Независимость
`MillisecondsDelta` от `Milliseconds` есть только в PascalABC.NET с
коммита 28.04.2026 (3.11.0.3812). В более старых версиях любой вызов
`Milliseconds` сбрасывает базу дельты, и часы игры почти стоят. Отбрасывание
долей миллисекунды в новой реализации — AUD-06.

## 4. Ввод

- GraphABC вызывает обработчики (`OnKeyDown`, `OnMouseDown`, …) в потоке
  окна; программа работает в главном потоке. `Control_AI` пишет из
  обработчиков в общую запись `Input`, программа читает её между кадрами.
- Клавиша и кнопка мыши — `TButtonState` (`Held`, `Pressed`, `Released`).
  `UpdateInput` в конце кадра гасит `Pressed`/`Released` клавиш и
  `Released` мыши; **`Pressed` мыши гасит тот, кто клик обработал**
  (`ClearMouseButtonPressed`) — так клик не теряется между кадрами.
- Кнопки мыши: 1 — левая, 2 — правая; другие `Control_AI` отбрасывает.
- `GetMousePos` — позиция последнего события мыши (нажатия или
  движения), а не позиция нажатия (AUD-03).
- Клавиши — сырые коды Win32: `R` = 82, `M` = 77, `P` = 80; `VK_ESCAPE`,
  `VK_SPACE`.

Известные отступления: непогашенные нажатия переходят между экранами
(AUD-02), нажатия клавиш во время кадра теряются (AUD-16).

## 5. Цель — `TCircle`

| поле | смысл |
|---|---|
| `X`, `Y` | центр, целые пиксели |
| `Time` | оставшаяся жизнь, мс; при появлении = `MaxCTime` |
| `SpawnTime` | `TryTime` в момент появления — начало отсчёта реакции |
| `CType` | 0 — ЛКМ, 1 — ПКМ (только Dual) |
| `SizeFactor` | 0,65…1,35 — масштаб этой цели |
| `IsBomb` | бомба |
| `VX`, `VY` | скорость в px/мс (только Tracking) |
| `HoverMs` | накопленная наводка (только Tracking) |

- **`Spawn`.** Масштаб, затем место: в окне с полями `effR =
  MaxRadius·SizeFactor`, снизу ещё 60 px под HUD, в Dual сверху 50 px под
  подсказку; не ближе `2·effR` к прежнему центру (до 100 попыток).
  Бомба — с вероятностью 15 %, кроме первой цели забега (`TryTime = 0`) и
  режима Tracking. В Tracking — случайное направление, 60…119 px/с.
- **`Update`.** Tracking: сдвиг на `Round(V·FrameTime)` и отскок от
  границ по `MaxRadius` (AUD-04, AUD-18). Затем `Time -= FrameTime`; при
  `Time < 0` и не бомбе — `Inc(Loses)`. Новую цель после истечения
  ставит вызывающий (`UpdateGame`).
- **`CurrentRadius`.** Tracking — постоянный `MaxRadius·SizeFactor`.
  Остальные — треугольник: рост от 0 до пика за первую половину жизни
  (`CCTime = MaxCTime div 2`), затем сжатие до 0.
- **`Render`.** Не рисуется на первом кадре (`Time >= MaxCTime`) и при
  радиусе 0. Бомба — тёмный круг с белым крестом. Обычная — цвет темы по
  `CType`, кольца на 50 % и 25 % радиуса (ориентир точности); в Tracking
  — кольцо прогресса наводки.
- **`GetHitInfo`.** Попадание — расстояние ≤ текущего радиуса. Бомба
  засчитывается любой кнопкой. Classic — только ЛКМ; иначе кнопка должна
  совпасть с `CType` (у Flick `CType = 0`, то есть ЛКМ). Точность
  попадания `1 − dist/r`.
- **`UpdateHover`** (Tracking): курсор на цели — `HoverMs += FrameTime`,
  иначе `−2·FrameTime` до нуля; `HoverMs ≥ 900` — цель засчитана.

## 6. Режимы

| режим | `TGameMode` | жизнь цели | как засчитывается |
|---|---|---|---|
| Classic | `gmClassic` | `Settings.LifetimeMs` | клик ЛКМ |
| Dual | `gmDual` | `Settings.LifetimeMs` | ЛКМ по цели `CType=0`, ПКМ по `CType=1` |
| Tracking | `gmTracking` | `Settings.LifetimeMs` | 900 мс наводки; клики не читаются |
| Flick | `gmFlick` | 400 мс, без учёта настройки | клик ЛКМ |

Описание для меню — `InitModes` (`TMenuMode`: имя, текст, цвета, тип
анимации превью, `Implemented` — сейчас у всех `true`).

## 7. Счёт и метрики забега (`TGameState`)

| величина | как считается |
|---|---|
| очки за попадание | `Round(13 / SizeFactor · mult)`; `mult` = 1, 1,5 при серии ≥ 5, 2 при ≥ 10; Tracking — без множителя |
| `Hits` | попадания кликом |
| `TotalShots` | все клики, включая промахи и клик по бомбе |
| Accuracy | `Hits / TotalShots · 100` |
| Precision | среднее `1 − dist/r` по попаданиям, % |
| реакция | `TryTime − SpawnTime` на момент обработки клика; Avg — среднее по попаданиям (AUD-06) |
| жизни | `MaxLoses = Settings.Lives`; минус одна за истёкшую цель (не бомбу) и за промах кликом |
| конец забега | жизни кончились, клик по бомбе (`DiedToBomb`) или `Esc` |
| `Combo` | +1 за попадание, 0 за промах кликом; истечение цели серию не рвёт (AUD-26) |

В Tracking `Hits` и `TotalShots` не меняются: Accuracy, Precision и Avg
— метрики кликовых режимов.

## 8. Данные игрока

Все файлы — в **текущем каталоге** процесса (AUD-17). Профиль `N` —
1…4 (`MAX_PROFILES`); при запуске всегда 1 (AUD-21).

| файл | когда пишется | что |
|---|---|---|
| `profileN_stats.ini` | при первом запуске профиля, в конце игры, при разблокировке достижения, при изменении настроек и туториала | всё, кроме истории сессий |
| `profileN_sessions.csv` | в конце каждой сохранённой игры (дописывается) | история сессий |
| `profileN_corrupt_backup.txt` | если `LoadStats` упал на разборе | копия повреждённого файла; одна, перезаписывается |
| `export_profileN_ГГГГММДД.csv` | кнопка «Экспорт в CSV» в «Истории» | копия `profileN_sessions.csv` |

### 8.1. `profileN_stats.ini`

Строки `ключ=значение`; заголовки секций для человека — разбор их
пропускает (в строке нет `=`). Неизвестные ключи игнорируются.
Вещественные — с точкой (главный поток в культуре `en-US`). Логические —
`True`/`False`.

| секция | ключ | тип, диапазон |
|---|---|---|
| `[Stats]` | `BestScore` | целое |
| | `BestAccuracy`, `BestPrecision` | вещественное, % |
| | `BestAvgReaction` | вещественное, мс; 0 — нет данных |
| | `GamesPlayed` | целое |
| | `TutorialSeen` | логическое |
| `[Settings]` | `ShowMainMenuEffects`, `SetSoundEnabled` | логическое |
| | `SetCircleSize` | 20…60, шаг 2 (по умолчанию 40) |
| | `SetLifetimeMs` | 500…2000, шаг 100 (1000) |
| | `SetLives` | 5…30 (15) |
| | `CurrentTheme` | 0 — Тёмная, 1 — Неон, 2 — Минимализм |
| `[ReactionHistory]` | `ReactionCount` | 0…50 |
| | `ReactionIndex` | 0…49 — следующая запись кольца |
| | `Reaction0` … `Reaction49` | мс |
| `[Achievements]` | `Achv0` … `Achv7` | логическое |
| `[Leaderboard]` | `LBCount0` … `LBCount3` | 0…10, режим по `Ord(TGameMode)` |
| | `LB{режим}{место}S`, `LB{режим}{место}A` | очки; точность, % |

Проверка диапазонов при загрузке — только у настроек и темы (AUD-07).
Ошибка разбора (`StrToInt`/`StrToFloat`) — бэкап и сброс всего на
умолчания с перезаписью файла.

### 8.2. `profileN_sessions.csv`

Заголовок `Date,Time,Hour,Mode,Score,Accuracy,AvgReaction,Hits,Misses,MaxCombo`;
`Date` — `ГГГГ-ММ-ДД`, `Time` — `ЧЧ:ММ`, `Mode` — `Classic` / `Dual` /
`Tracking` / `Flick`, `Accuracy` и `AvgReaction` — один знак после
точки, `Misses` — промахи кликом (`WrongClicks`), не истёкшие цели.
«История» читает до 500 первых строк (AUD-15).

### 8.3. Совместимость

Формат не версионирован. C++-версия читает и пишет тот же формат, но в
папке пользователя, а не в текущем каталоге (D-11); папка, порядок записи
и номер последнего профиля в `aim_trainer.ini` — D-30, §12 «Файлы игрока».

## 9. Меню и панели

- Верх: плашка превью режима слева (`PLATE_*`), кнопки режимов и
  описание справа (`BTNS_*`, `DESC_*`); середина — график последних
  50 реакций (`DrawGraph`, кривая Безье, шкала 0–1000 мс; AUD-14); низ —
  лучшие результаты и кнопки «Справка», «Настройки», «Рекорды»,
  «Награды», «История», «Профиль N», подпись «Effects: ON/OFF».
- Панели поверх меню — флаги `Show*`; клик сначала получает та, что
  выше в `UpdateMenuInput`: туториал → справка → рекорды → награды →
  история → профили → настройки → нижние кнопки → кнопка режима →
  плашка → иначе переключение эффектов. `Esc` закрывает открытую панель.
- Геометрия каждой кнопки задана дважды — в отрисовке и в `IsIn*`
  (AUD-24).

## 10. Эффекты, звук, темы, достижения

- **Эффекты** — кольцевой буфер `Effects[0..99]` без очистки: тип 0 —
  вспышка, 1 — волна, 2 — осколок, 3 — текст очков, 4 — белая вспышка
  экрана (точность ≥ 95 %), 5 — красная (бомба). Попадание порождает 11–12
  эффектов (до 700 мс). След курсора — 12 точек (`TrailPoints`).
- **Частицы меню** — 100 штук, линии между близкими (< 100 px) и к
  курсору (AUD-13, AUD-20, AUD-27).
- **Звук** — `System.Console.Beep`, синхронный: попадание 1000 Гц/30 мс,
  промах 300 Гц/40 мс, конец игры 200 Гц/220 мс (AUD-06).
- **Темы** — фон и два цвета целей; текст везде белый/серый, поэтому все
  три темы тёмные (`InitThemes`, `ApplyTheme`).
- **Достижения** (`InitAchievements`, `UnlockAchievement` — сразу
  `SaveStats` и уведомление на 3 с):

| № | название | условие | где проверяется |
|---|---|---|---|
| 0 | Первая игра | `GamesPlayed = 1` | `FinishGameAndSaveStats` |
| 1 | В яблочко | точность попадания ≥ 0,95 | `ProcessClick` |
| 2 | Молниеносно | реакция < 150 мс | `ProcessClick` |
| 3 | Комбо x100 | `Combo ≥ 100` | `ProcessClick` |
| 4 | Тысяча | `Score ≥ 1000` за игру | `ProcessClick` |
| 5 | Снайпер | ≥ 20 выстрелов и Accuracy ≥ 90 % | `FinishGameAndSaveStats` |
| 6 | Ветеран | `GamesPlayed ≥ 1000` | `FinishGameAndSaveStats` |
| 7 | Мастер Dual | Dual и `Score ≥ 500` | `FinishGameAndSaveStats` |

- **Туториал** — 4 экрана при `TutorialSeen = False`; клик листает, `Esc`
  пропускает.

## 11. Особенности среды PascalABC.NET

Сверено по исходникам `bin/Lib/PABCSystem.pas` и `bin/Lib/GraphABC.pas`
(3.9.0.3422 и 4.0.0.3886). Опираясь на поведение библиотеки, сверять его
с исходником нужной версии, а не с памятью (`CLAUDE.md`). Исходники
4.0.0.3882 эталона в сессии — `$PABCNET_DIR/bin/Lib` (D-26).

| что | как на деле |
|---|---|
| `Milliseconds` / `MillisecondsDelta` | до 3.11.0.3812 (28.04.2026) делят одну точку отсчёта — `Milliseconds` сбрасывает дельту; позже — независимы, на `Stopwatch`, дельта в целых мс с отбрасыванием остатка |
| `Round(x)` | `Convert.ToInt32(x)` — банковское округление: `Round(0.5) = 0`, `Round(1.5) = 2` |
| `Random(a, b)` | целое в `[a, b]` включительно; при `a > b` границы меняются местами |
| `ARGB`, `RGB` | параметры `byte`: отрицательное или > 255 целое оборачивается, а не обрезается (AUD-13) |
| `Format`, `StrToFloat`, `real.ToString` в главном потоке | точка как разделитель: культура потока `en-US`, `nfi` с точкой |
| события GraphABC | в потоке окна (`MainFormThread`), не в главном |
| кодировка исходников | UTF-8 без BOM распознаётся компилятором по содержимому |
| `Console.Beep` | синхронный: поток стоит всё время звука |
| файлы `Text` (`Rewrite`, `Writeln`) | кодировка `DefaultEncoding` — Windows-1251, а где её нет — UTF-8 без BOM (`__InitModule`); перевод строки — `Environment.NewLine`: CRLF на Windows, LF под Mono на Linux. Файлы профиля — только ASCII. `real.ToString` — до 15 значащих цифр (`46.1538461538462`) |
| `FillRoundRect`, `DrawRoundRect` | скругления — дуги `GraphicsPath.AddArc` размером `w`×`h` (`CreatePathForDrawRoundRect`, `GraphABCHelper.pas`); при `w` или `h` = 0 GDI+ отвечает `InvalidParameter` → `ArgumentException`: под Mono — прогоном, на Windows — по тесту `AddArc_ZeroWidthHeight_ThrowsArgumentException` (dotnet/winforms). Оригинал рисует так три экрана — сценарий 22 `docs/MANUAL_CHECKS.md` |

## 12. C++-версия

Перенос идёт шагами `task-cpp` (`ROADMAP/ROADMAP.md`); сейчас в C++-версии
— окно, главный цикл, время клика, логика игры без окна (цели, режимы,
забег, профиль), файлы профиля и истории в папке игрока, переходы экранов
и временный интерфейс: в Classic, Dual, Tracking и Flick уже можно
играть, рекорды и история сохраняются. Настоящих экранов образца и звука
ещё нет. Сборка — `docs/BUILD.md`; слои и пресеты — D-25.

```
src/app/main.cpp            AimTrainer: окно 800×600, главный цикл
  screens.h, .cpp           временные экраны: меню, отсчёт, игра, Game Over
  draw.h, .cpp              круги, линии, текст отладочным шрифтом SDL
  player_files.h, .cpp      файлы игрока: какой профиль, когда писать, что сказать
src/platform/               aim_platform: SDL3 и ОС
  raw_mouse.h               свой поток сырого ввода мыши (D-24)
  raw_mouse_win.cpp         — Windows
  raw_mouse_none.cpp        — другие системы: потока нет
  storage.h, .cpp           папка игрока: чтение, запись целиком, дописывание
src/core/                   aim_core: логика без окна, без SDL и ОС (D-20)
  time.h, mouse.h           наносекунды часов программы; кнопки мыши
  random.h, .cpp            случайные числа — как Random образца
  rounding.h                банковское округление — как Round образца
  rules.h                   числа правил: поля, масштаб, бомбы, очки, серия
  modes.h, .cpp             режимы и правила цели в каждом (D-21)
  target.h, .cpp            цель — перенос TCircle
```

**Логика без окна.** Часов не читает: время ей передаёт программа
(`SDL_GetTicksNS`), случайные числа — интерфейс `Random` (в тестах —
заданная последовательность). Всё — абсолютные моменты, а не остаток
жизни, как у образца:

- *Цель* (`Target`) знает момент появления, конец жизни и первый показ.
  Радиус — на любой момент: растущая (Classic, Dual) — треугольник 0 → пик
  → 0, Flick и Tracking — сразу пик (D-21). Засчитать можно только
  показанную и живую цель; радиус и точка — на момент щелчка (AUD-03).
  Tracking: вещественные координаты и отскок по своему радиусу выше HUD
  (AUD-04, AUD-18); наводка копится на цели и тает вдвое быстрее вне её.
- *Забег* (`Game`): в кадре программа сначала отдаёт щелчки (`click`, со
  временем щелчка), потом `update(now)`, потом рисует и сообщает о показе
  (`frame_presented`): реакция — от показа первого кадра с целью (D-12).
  Щелчок, сделанный до истечения цели, засчитывается по ней, даже если
  разобран после. Серию обрывают промах и истёкшая обычная цель (D-14).
  Пауза сдвигает моменты цели на свою длину. Что видно и слышно — события
  `take_events`: попадание, промах, бомба, истечение, наводка.
- *Профиль* (`Profile`): рекорды точности и реакции — от 20 выстрелов
  (D-13); таблица лидеров — все четыре режима (AUD-09); история реакций —
  последние 50 по порядку (AUD-14); достижения — по событиям забега и
  итогу, условия как у образца (§10). Текст файлов — `core/profile_file.h`
  и `core/history.h`, ниже.

**Поток сырого ввода (D-24, Windows).** Своё окно `HWND_MESSAGE` в своём
потоке; мышь зарегистрирована `RegisterRawInputDevices` без флагов — ввод
приходит, пока программа впереди; приоритет `THREAD_PRIORITY_TIME_CRITICAL`.
На `WM_INPUT` с нажатием — метка `SDL_GetTicksNS` и логическая кнопка
(перестановка для левши — как у SDL: только у настоящего устройства).
Нажатия из касаний и пера отброшены. Приёмник сырого ввода мыши — один на
процесс: второй экземпляр не запускается, а режим relative SDL программа не
включает.

**Время клика.** На `SDL_EVENT_MOUSE_BUTTON_DOWN` главный цикл забирает
сырые нажатия и спрашивает `ClickTimer`: сырое нажатие той же кнопки в
окне от «метка SDL − 10 мс» до «метка SDL + 26 мс» — время клика; нет —
метка события SDL, и источник виден. Окно несимметричное: на Windows метка
SDL — `msg.time`, раньше настоящего нажатия на 0…16 мс (шаг счётчика
тиков). Сырое нажатие и событие SDL приходят в два потока одновременно, и
событие изредка разбирается раньше, чем поток поставил метку (под Wine — 2
клика из 300, метка позже на 0,1–0,9 мс): тогда цикл ждёт сырое нажатие
`RawMouse::wait_for_press` — не дольше 2 мс и пока оно ещё попадёт в окно,
то есть до «метка SDL + 26 мс»; поток будит ожидание сразу, как поставил
метку. SDL держит таймер Windows с шагом 1 мс (`timeBeginPeriod(1)` в
`SDL_InitTicks`), так что напрасное ожидание — около 2 мс, и только у клика
без сырого нажатия. Сырые нажатия без события SDL (клик по заголовку, мимо
окна) выбрасываются и следующему клику не достаются. Касание и перо (`which` —
`SDL_TOUCH_MOUSEID`, `SDL_PEN_MOUSEID`) — со временем события SDL.

**Главный цикл** (`src/app/main.cpp`). Кадр: разобрать очередь SDL —
щелчок получает точку из события и время из `ClickTimer` (сырой ввод,
D-24), клавиша — время события, по физическому положению (`scancode`:
P, R, M работают и в русской раскладке), автоповтор отброшен; затем
`Flow::input` и `Flow::update` на время кадра `SDL_GetTicksNS` (без
отбрасывания долей миллисекунды, AUD-01, AUD-06), рисование, показ и
`Flow::frame_presented` — с момента показа идёт реакция (D-12). Предел —
240 кадров в секунду, как у образца (`SDL_DelayPrecise` на остаток). Итог
щелчка — в заголовке окна (сценарий 21). Экраны — `core/flow.h` (переходы,
ввод экранам) и временный интерфейс `src/app/screens.cpp`: четыре кнопки
режимов, отсчёт, цель, строка HUD, пауза, Game Over с тепловой картой —
отладочным шрифтом SDL (только ASCII) до шага «Экраны». Файлы игрока —
ниже.

**Экраны и переходы** (`core/flow.h`) — как у образца (§2): меню → отсчёт
3 с → игра → Game Over; P — пауза, R — заново без записи, M — в меню с
записью, Esc — конец забега. Событие достаётся экрану, активному в момент
разбора; после смены экрана остальные события кадра отбрасываются, и
нажатие не переходит на следующий экран (AUD-02). Клавиши — события, а не
флаги, гаснущие в конце кадра (AUD-16). Забег начинается с конца
отсчёта, а не с кадра, который его заметил.

**Файлы игрока** (D-11, D-30). Формат — образца (§8.1, §8.2): файл,
записанный образцом, читается, и запись его не меняет — тест на файлах
эталона (`tests/core/profile_file_test.cpp`). Вещественные — как
`Double.ToString()` .NET (15 значащих цифр), перевод строки — системный.
Чтение — как `LoadStats`: значение известного ключа не число — копия
`profileN_corrupt_backup.txt` и профиль по умолчанию; настройки и тема
вне границ — к умолчанию. Сверх образца (AUD-07): кольцо реакций и
таблицы лидеров вне границ сбрасываются, соседние поля остаются; такой
профиль переписывается сразу. Папка — `SDL_GetPrefPath("", "AimTrainer")`:
на Windows `%APPDATA%\AimTrainer\`, на Linux `~/.local/share/AimTrainer/`;
`AIM_TRAINER_DATA_DIR` заменяет её (проверки, `tools/gui.sh port`).
Профиль пишется во временный файл и переименованием поверх старого
(`SDL_RenamePath`: `MoveFileExW` с `MOVEFILE_REPLACE_EXISTING`, `rename`),
история — дописывается. Номер последнего профиля — `aim_trainer.ini`
(`[App]`, `LastProfile=N`; AUD-21); профиль читается начисто, флаг
эффектов от прежнего не остаётся. Когда пишется — как у образца (§8):
новый профиль — сразу, конец забега (`RunFinished`) — профиль и строка
истории, достижение — сразу. Ошибка записи — уведомление в окне с именем
файла и причиной (AUD-17); нет папки — профиль только в памяти, и это
уведомление при запуске. «История» читает последние 500 игр, а не первые
(AUD-15); испорченная строка истории пропускается.

**SDL 3.4.18 на Windows — сверено по исходнику** (то, на чём стоит время
клика; при обновлении SDL — сверить заново, D-24):

| что | как на деле |
|---|---|
| метка события мыши | `WIN_GetEventTimestamp`: `msg.time` плюс сдвиг к `SDL_GetTicksNS`; сдвиг заводится по первому сообщению и только уменьшается — когда метка вышла бы позже «сейчас». Первые события после запуска бывают позже настоящих (под Wine первый клик — на 4,2 мс), дальше метка не позже нажатия |
| таймер Windows | `SDL_InitTicks` ставит `timeBeginPeriod(1)`: подсказка `SDL_HINT_TIMER_RESOLUTION`, по умолчанию 1 мс |
| сырой ввод мыши у самого SDL | только в режиме relative (`WIN_SetRelativeMouseMode` → `WIN_SetRawMouseEnabled`) и в эмуляции переноса курсора: курсор скрыт и дважды перенесён в центр окна (`SDL_MaybeEnableWarpEmulation`); сырая клавиатура (`SDL_HINT_WINDOWS_RAW_KEYBOARD`) регистрирует только клавиатуру |
| кнопки левши в сыром вводе | `WIN_SwapButtons`: переставляются только у события с устройством (`hDevice` не пуст); у сенсорной панели и `SendInput` — уже логические |
| заголовок окна на X11 (Linux) | `SDL_X11_SetWindowTitle`: `_NET_WM_NAME` — через `Xutf8TextListToTextProperty`; в локали процесса «C» (программа её не меняет, SDL возвращает прежнюю после настройки ввода) кириллица не проходит, и `_NET_WM_NAME` остаётся прежним, а `WM_NAME` получает байты UTF-8. Проверено под Xvfb 16 октября 2026. У оригинала заголовок — латиницей, «Aim Trainer»; кириллица — только в отладочном заголовке каркаса |
