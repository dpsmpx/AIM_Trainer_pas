# Перенос на C++

Aim Trainer переносится с PascalABC.NET на C++ и SDL3 (D-08, D-10, задача
`task-cpp` в `ROADMAP/ROADMAP.md`) и постепенно реализует весь функционал
оригинала. Оригинал — `archive/pascal/` — не правится: это образец
функционала и эталон (D-09, D-28). Перенос сверяется с ним не по описанию, а по
живой программе: один и тот же сценарий `docs/MANUAL_CHECKS.md` идёт на
обеих, снимки окна сравниваются. Образец — перенос TrueJointTileMaker
(`TrueJointTileMaker:docs/porting.md`).

Как устроен оригинал — `docs/ARCHITECTURE.md`, §1–11; что уже есть в
C++-версии — там же, §12. Сборка — `docs/BUILD.md`.

## 1. Что где

| путь | что |
|---|---|
| `archive/pascal/` | оригинал: `AIM_Trainer.pas`, `AimCircle.pas`, `Control_AI.pas`, `Base.pas` — образец и эталон (D-09, D-28) |
| `src/core/` | логика без окна: только стандартная библиотека C++ (D-20, D-25) |
| `src/platform/` | SDL3 и ОС: свой поток сырого ввода мыши (D-24) |
| `src/app/` | программа: окно и главный цикл |
| `tests/` | тесты по тем же слоям; программа целиком — кадры без экрана |
| `CMakeLists.txt`, `CMakePresets.json`, `tools/cmake/` | сборка C++-версии (D-19, D-25) |
| `tools/setup_env.sh` | установка всех инструментов, и эталона тоже (D-26) |
| `tools/check_cpp.sh` | проверка C++-версии одной командой (D-25) |
| `tools/gui.sh` | сборка, запуск, ввод и снимки окон оригинала (`ref`) и C++-версии (`port`) без экрана (D-26) |
| `tools/pabcnet/` | заплатка компилятора PascalABC.NET для Mono 6.8 (D-26) |
| `tools/helpers/` | боты, замеры и отладочные заплатки сессий (D-27) |
| `tools/lib_probes/` | замерщики ввода, по которым выбрана библиотека (`docs/LIB_PROBES.md`, D-24) |

Шаги переноса и их порядок — `ROADMAP/ROADMAP.md`; что C++-версия обязана
исправить по сравнению с оригиналом — `TODO.md`, «Требования к
C++-версии».

## 2. Сборка обеих версий

```sh
tools/setup_env.sh                 # один раз; в облачной сессии — хук
tools/check_cpp.sh                 # C++-версия: все пресеты сессии и тесты
tools/gui.sh ref build             # archive/pascal под Mono → build/ref/AIM_Trainer.exe
tools/gui.sh port build            # C++-версия, пресет linux-gcc
```

У автора на Windows — только C++-версия, пресет `windows`
(`docs/BUILD.md`, §1): оригинал там больше не прогоняется (D-28).

## 3. Сверка с эталоном

1. Обе программы — в своих Xvfb: `tools/gui.sh ref start`,
   `tools/gui.sh port start`.
2. Один и тот же сценарий — те же команды `click`, `key`, `move` с теми же
   координатами окна; где нужно попадать по целям —
   `tools/helpers/ref_bot.py` (правила — в его шапке).
3. Снимки — `tools/gui.sh TARGET shot`, сравнение —
   `tools/gui.sh compare A.png B.png [DIFF.png]` (число несовпавших
   пикселей).

Что сравнивать:

- **Неподвижные экраны** — меню с выключенными эффектами, панели
  настроек, истории, рекордов, справки, Game Over: раскладка, размеры,
  цвета, кнопки. Цели и частицы случайны (`Randomize`), их кадры
  попиксельно не совпадут.
- **Текст** — по месту и ширине, а не попиксельно: под Mono оригинал
  пишет через libgdiplus и cairo, Consolas подменён DejaVu Sans Mono
  (D-22) — тем же шрифтом, что у C++-версии.
- **Поведение** — по сценариям `docs/MANUAL_CHECKS.md`: столбец «сейчас»
  и раздел «Эталон под Mono» — что делает оригинал; C++-версия обязана
  пройти все сценарии.

Чего эталон под Mono не показывает: частоту кадров и время Windows
(AUD-01, AUD-25), текст GDI+, звук `Console.Beep`. Здесь образец —
чтение кода и `docs/ARCHITECTURE.md`.

Оригинал падает на трёх экранах — точное попадание, подрыв, пауза
(сценарий 22): сценарии с ними на эталоне не пройти, сверка там — по коду
(`RenderEffects`, `RenderPauseOverlay`) и ожиданиям сценария.

## 4. Поведение, которое легко потерять

Найдено аудитом, прогоном эталона и чтением исходников PascalABC.NET
(`docs/ARCHITECTURE.md`, §11). Где C++-версия нарочно ведёт себя иначе —
сказано и дана ссылка.

- **Округление.** `Round` — `Convert.ToInt32`, банковское: половина к
  чётному. В C++ — `std::nearbyint` при режиме по умолчанию, не
  `std::lround`.
- **Случайные числа.** `Random(a, b)` — включительно с обеих сторон,
  `Random(n)` — от 0 до n−1; при `a > b` границы меняются местами.
- **Числа в файлах.** Точка как разделитель; вещественные — до 15
  значащих цифр; логические — `True`/`False`. Формат файлов профиля
  и истории — `docs/ARCHITECTURE.md`, §8; C++-версия читает и пишет его
  же (D-11), CRLF и LF при чтении — оба. Проверка диапазонов при чтении —
  в C++-версии есть, у оригинала нет (AUD-07: при неверных счётчиках он
  падает при запуске).
- **Время.** `Milliseconds` и `MillisecondsDelta` до 3.11.0.3812 делят одну
  точку отсчёта (AUD-01); C++-версия берёт монотонные часы SDL, реакцию —
  от показа кадра с целью (D-12), время клика — из своего потока сырого
  ввода (D-24).
- **Ввод.** События GraphABC приходят в поток окна, главный цикл опрашивает
  `IsMouseButtonPressed` раз в кадр и снимает нажатие
  `ClearMouseButtonPressed` — не везде, и клик переходит на следующий
  экран (AUD-02, подтверждено прогоном). Попадание проверяется по курсору
  в момент обработки (AUD-03). В C++: точка — из события SDL, событие
  достаётся одному экрану.
- **Экраны — вложенные циклы.** `StartScreen`, `CountdownScreen`,
  `GameLoop`, `GameOverScreen` — каждый со своим `while`; панели меню —
  флаги `ShowHelp`, `ShowSettings` и другие поверх меню
  (`docs/ARCHITECTURE.md`, §2, §9). Такую структуру можно перенести как
  есть, если каждый цикл сам разбирает очередь событий SDL.
- **Целые координаты Tracking.** `X += Round(VX * FrameTime)`: при кадре
  4 мс сдвиг меньше 0,5 px округляется в 0, и цель стоит; при 5–8 мс — шаг
  0 или 1 px по оси, и направление прилипает к осям и диагоналям (AUD-04,
  подтверждено прогоном); в C++ — вещественные координаты и параметры
  D-21.
- **Цвет с прозрачностью.** `ARGB` принимает `byte`: отрицательное
  значение оборачивается, и линии к курсору на 100 px резко ярче (AUD-13);
  в C++ — ограничивать 0…255.
- **Скругление 0.** `FillRoundRect(…, 0, 0)` в GraphABC — дуги нулевого
  размера, GDI+ отвечает ошибкой, и оригинал падает (сценарий 22); в C++
  такие места — обычные прямоугольники.
- **Звук.** `Console.Beep` синхронный: кадр стоит всё время звука
  (AUD-06); в C++ — SDL3, не задерживая кадр.
- **Частота кадров.** `LimitFrameRate` спит `Sleep` до 4 мс; на Windows без
  повышенного разрешения таймера это ~64 кадра в секунду (AUD-25,
  UNVERIFIED), под Mono — 254–276.
- **Нарочно иначе в C++** (решения автора): параметры Tracking и Flick
  (D-21), рекорды от 20 выстрелов (D-13), комбо обрывает и пропущенная
  цель (D-14), лидеры всех четырёх режимов (AUD-09), история — последние
  500 игр (AUD-15), файлы — в папке пользователя (D-11).
