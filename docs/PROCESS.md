# Процесс

Пояснения к правилам `CLAUDE.md`: зачем они и откуда. Правила — там; здесь
— почему.

## Какой документ когда менять

| Документ | Отвечает на вопрос | Меняется |
|---|---|---|
| `docs/direction/DECISIONS.md` | что решено и почему | новым решением; старое — «заменено D-NN» |
| `CLAUDE.md` | правила, обязательные при каждом изменении | вместе с решением, которое их меняет |
| `ROADMAP/ROADMAP.md` | этапы, порядок, состояние | флажок — в задаче, которая сделала шаг |
| `TODO.md` | хвосты, подтверждённый долг, вопросы автору | сделанное удаляется в той же задаче |
| `docs/ARCHITECTURE.md` | как устроено сейчас | в том же PR, что и код, который меняет описанное |
| `docs/MANUAL_CHECKS.md` | чем проверить правку на Windows | новым сценарием вместе с правкой кода |
| `docs/audits/*.md` | что было найдено на дату | не меняется; следующий аудит — новым файлом или разделом с датой |
| `docs/CHANGELOG.md` | вехи: этапы, выпуски | при закрытии этапа ROADMAP или выпуске, не на каждый коммит |
| `docs/PROVENANCE.md` | откуда код и на каком основании | с каждой чужой частью или сменой способа разработки |
| `README.md` | витрина для игрока | только по запросу автора (D-06) |
| описание PR | Сделано / Осталось / Проверки | с каждым пушем |

## Откуда правила

Каркас повторяет process-kit, который сложился в Galdhold и обобщается
в DP-Verify (`Galdhold:tools/dpv/kit`), и правила DPmeta о видах записей
и аудите (`DPmeta:docs/doc-audit/TASK.md`). Различия — ниже.

- **Решение — с проверкой.** Решение, которое ничто не ловит, тихо
  перестаёт выполняться; проверка делает отступление видимым.
- **Решение по факту — не выбор автора.** Аудит записал в журнал то, что
  уже действует (платформа, формат файлов, лицензия), с пометкой «записано
  аудитом, подтверждение автора — открыто». Иначе журнал выдал бы
  наблюдение за решение (так различает DPmeta: `DPmeta:docs/DECISIONS.md`,
  M-03).
- **Сделанное удаляется из `TODO.md`.** Список, где выполненное
  смешано с невыполненным, перестают читать.
- **Красное до правки — не своё.** Задача, расширенная ради чужой
  поломки, не заканчивается; поломка записывается и чинится отдельно.
- **Пустая проверка — провал.** Проверка, которой нечего проверять,
  выглядит как защита и ничего не защищает.

## Свои правила проекта и их причины

- **Ручные сценарии там, где сборки нет (D-07).** Pascal-версию хук
  сессии не собирает: GraphABC вне Windows собирается только под Mono с
  компилятором из исходников (так делает TrueJointTileMaker) — это шаг
  переноса «Эталон» (D-08). C++-версию сессия собирает и тестирует сама —
  `tools/check_cpp.sh` (D-25), — но замер реакции и сырой ввод видны
  только на Windows (D-24). Поэтому то, что видно только на Windows, —
  сценарии `docs/MANUAL_CHECKS.md` у автора, а сессия обязана честно
  писать «не компилировалось» или «на Windows не проверялось». До 13
  октября 2026 код менялся сессиями ИИ без сборки, и шапка файла сама это
  признавала (AUD-29).
- **Поведение библиотеки — по исходнику.** Главный дефект аудита
  (AUD-01) вырос из комментария, который уверенно описывал семантику
  `Milliseconds` — верную только для версий после апреля 2026.
  Исходники PascalABC.NET открыты; сверка стоит минут.
- **История — не в шапке файла.** Шапка-журнал `AIM_Trainer.pas`
  устарела за одну итерацию и стала источником неверных сведений об
  именах файлов и состоянии режимов (AUD-12). История — в Git, PR и
  `docs/CHANGELOG.md`.
- **README — витрина (D-06).** На 13 октября 2026 README расходился с
  кодом в лицензии, имени файла и версии среды (AUD-05, AUD-11).
- **Сценарий на каждую правку кода.** Без автоматических тестов
  единственная защита от возврата дефекта — сценарий, который его ловит;
  в `docs/MANUAL_CHECKS.md` у каждой находки он уже есть.

## Нумерация

| что | номер | где определён |
|---|---|---|
| решение | `D-NN` | `docs/direction/DECISIONS.md` |
| находка аудита | `AUD-NN` | `docs/audits/PROJECT_AUDIT.md`; следующий аудит продолжает счёт, та же проблема — тот же номер |
| ручной сценарий | номер строки таблицы | `docs/MANUAL_CHECKS.md`; номера не переиспользуются |
| этап | «Этап N», якорь `task-N` | `ROADMAP/ROADMAP.md` |

Номер другого проекта пишется с его именем: `DPmeta:M-03`,
`Galdhold:Р21`; путь — `DPmeta:docs/PRINCIPLES.md`
(`DPmeta:docs/NAMING.md`).

## Связь с экосистемой

- О себе прав сам репозиторий (`DPmeta:docs/DECISIONS.md`, M-02): если
  DPmeta или другой проект пишет о Aim Trainer иначе, чем здесь,
  исправляется он, а не этот журнал.
- На 13 октября 2026 Aim Trainer в реестре DPmeta нет (AUD-28) —
  предусловие в `TODO.md`.
- Различия с Galdhold и DPmeta, оправданные назначением:
  - репозиторий **публичный** и под GPL v3 — правил закрытости Galdhold
    («код наружу не уходит») здесь нет;
  - вместо DP Verify — `tools/check_docs.py` и ручные сценарии (D-01, D-07);
  - детерминизм (`DPmeta:docs/PRINCIPLES.md`, E-12) не применяется: игра
    нарочно случайна; воспроизводимость нужна замеру (AUD-06), а не
    появлению целей.
