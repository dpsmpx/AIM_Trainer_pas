# Решения

Журнал решений. Это источник истины: если другой документ расходится с
решением, прав журнал, а расходящийся исправляется.

Правила журнала:

- Номер — `D-NN` латиницей; не переиспользуется и не меняется. Новое
  решение — следующий свободный номер (последний принятый — D-08).
- Решение не переписывается задним числом. Если оно меняется, старое
  получает статус «заменено D-NN», а новое объясняет, что изменилось и
  почему.
- У каждого решения есть **Статус.** — кем и когда принято. Записанное
  аудитом по факту репозитория помечено так и ждёт подтверждения автора:
  это описание того, что есть, а не выбор за автора.
- У каждого решения есть **Проверка.** — команда, сценарий или обзор,
  который ловит отступление. Решение без проверки — пожелание.

Форма записи: **Статус.**, **Решение.**, **Почему.**, **Следствия.**,
**Проверка.**, **Отклонено.**

## Принятые

### D-01 — Документация и процесс — по образцу Galdhold и DPmeta

**Статус.** Принято — поручение автора 13 октября 2026 («создай и наполни
каркас документации на основе Galdhold, DPmeta»).

**Решение.** Правила работы — `CLAUDE.md`; решения — этот журнал; этапы —
`ROADMAP/ROADMAP.md`; незаконченное — `TODO.md`; как устроено сейчас —
`docs/ARCHITECTURE.md`; аудиты на дату — `docs/audits/`. Форма
документов — process-kit (`Galdhold:tools/dpv/kit`), виды записей и шкалы
аудита — как в DPmeta (`DPmeta:docs/doc-audit/TASK.md`).

**Почему.** До 13 октября 2026 в репозитории был только README: решения,
состояние и долг жили в комментарии-шапке главного файла и устарели
вместе с ним (AUD-12). Общая форма с другими проектами автора позволяет
сессиям и автору читать проект так же, как остальные.

**Следствия.** Новый документ — в свой каталог (`CLAUDE.md`, «Где лежат
не-кодовые файлы»). История правок — в Git, PR и `docs/CHANGELOG.md`, а не
в комментариях кода.

**Проверка.** `python3 tools/check_docs.py`: корень, ссылки, поля решений,
форма `TODO.md` и `ROADMAP`.

**Отклонено.** Поставка DP Verify в `tools/dpv/` сейчас: в сессии нет
компилятора PascalABC.NET, и общие проверки свелись бы к документам,
которые закрывает `tools/check_docs.py`. Поставка — отдельное решение
этого репозитория (`DPmeta:docs/ECOSYSTEM.md`, §3).

### D-02 — Платформа: PascalABC.NET и GraphABC, Windows, окно 800×600

**Статус.** Действует по факту (код и README на 13 октября 2026);
записано аудитом, подтверждение автора — открыто.

**Решение.** Программа — на PascalABC.NET с графикой GraphABC из
поставки среды, без внешних библиотек. Целевая система — Windows. Окно —
800×600 фиксированного размера; раскладка интерфейса задана в пикселях
под этот размер. Исходники — в корне: модули из `uses` среда ищет рядом с
программой.

**Почему.** Так проект задуман и написан (README, «Обзор» и «Запуск»);
GraphABC не требует установки ничего, кроме PascalABC.NET.

**Следствия.** Версия среды должна давать независимые `Milliseconds` и
`MillisecondsDelta` — PascalABC.NET от 28.04.2026 (3.11.0.3812) и новее,
пока код опирается на это (AUD-01); README пока обещает «3.8 или новее».
Сборку и запуск в облачной сессии не проверить — только у автора на
Windows. Опираясь на поведение библиотеки, сверять исходник версии
(`docs/ARCHITECTURE.md`, §11). Решение действует, пока перенос на C++ не
достигнет возможностей этой версии; затем заменяется (D-08).

**Проверка.** Ручная: сборка `F9` и сценарии `docs/MANUAL_CHECKS.md` на
названной версии среды; версия — в описании PR.

**Отклонено.** —

### D-03 — Лицензия — GNU GPL v3 (файл `LICENSE`)

**Статус.** Действует по факту: файл `LICENSE` (GNU GPL v3) — в первом
коммите `9857adf`, 5 июля 2026. Записано аудитом. README в одном месте
называет MIT — **открытый вопрос автору** (AUD-05).

**Решение.** Код распространяется на условиях файла `LICENSE`.

**Почему.** Юридически действует текст лицензии в репозитории, а не
подпись в README.

**Следствия.** Чужой код — только совместимый с GPL v3 и с записью в
`docs/PROVENANCE.md`. Смена лицензии — только новым решением автора;
исправление README — по D-06.

**Проверка.** Обзор при каждом аудите: README, `LICENSE` и шапки модулей
называют одну лицензию.

**Отклонено.** —

### D-04 — Данные игрока — файлы профиля в текущем каталоге

**Статус.** Действует по факту (код на 13 октября 2026); записано
аудитом, подтверждение автора — открыто.

**Решение.** До 4 профилей; у профиля `N` — `profileN_stats.ini`
(`ключ=значение`) и `profileN_sessions.csv`; файлы пишутся в текущий
каталог процесса. Формат — `docs/ARCHITECTURE.md`, §8.

**Почему.** Простейший способ без зависимостей; файл читается
человеком и открывается в Excel.

**Следствия.** Файлы игрока — личные данные: в репозиторий не
попадают. Совместимость со старыми файлами не определена — вопрос
автору (`TODO.md`); пока его нет, смена формата допускается, но
описывается в `docs/ARCHITECTURE.md` в том же PR.

**Проверка.** `docs/MANUAL_CHECKS.md`, сценарии 12–14; обзор: в
`git ls-files` нет `profile*` и `export_*`.

**Отклонено.** —

**Почему.** Так написан проект и все проекты автора; латинские номера не
путаются с кириллическими.

**Следствия.** —

**Проверка.** Обзор.

### D-06 — README — витрина, а не источник истины

**Статус.** Принято — сессия Claude при создании каркаса, 13 октября 2026,
по образцу Galdhold, DPpass, DPprofile, DPlearn
(`DPmeta:docs/PRINCIPLES.md`, E-13). Обычное решение, обратимо: автор
может заменить.

**Решение.** На README не опираются в выводах о состоянии и устройстве
проекта: состояние — код, этот журнал, `ROADMAP`, `TODO.md`; устройство
— `docs/ARCHITECTURE.md`. README меняется только по запросу автора;
найденные в нём ошибки записываются в `TODO.md` с предлагаемым текстом.

**Почему.** README пишется для читателя витрины и устаревает первым:
на 13 октября 2026 в нём неверны лицензия, имя главного файла и
требование к среде (AUD-05, AUD-11).

**Следствия.** Технический раздел README дублирует
`docs/ARCHITECTURE.md`; при расхождении прав `docs/ARCHITECTURE.md`.

**Проверка.** Обзор при аудите; `tools/check_docs.py` README не
проверяет.

**Отклонено.** Исправить README в том же PR, что и каркас: правка
лицензии — решение автора (AUD-05), остальное — по его запросу.

### D-07 — Без GitHub Actions; проверка — командой в сессии и руками на Windows

**Статус.** Действует по факту (каталога `.github/workflows` нет) и
совпадает с принципом экосистемы (`DPmeta:docs/PRINCIPLES.md`, E-07);
записано при создании каркаса. Обычное решение, обратимо.

**Решение.** В сессии — `python3 tools/check_docs.py`. Код — сборкой и
сценариями `docs/MANUAL_CHECKS.md` у автора на Windows. Итог проверок —
в описании PR, включая «не компилировалось», если сборки не было.

**Почему.** В сессии нет ни PascalABC.NET, ни Mono, сеть до
pascalabc.net закрыта. Вне Windows программу на GraphABC собирают только
под Mono с WinForms, компилятором из исходников и заплаткой — так делает
TrueJointTileMaker (`TrueJointTileMaker:docs/porting.md`); здесь это не
настроено. Зелёный значок от проверки одних документов выдавал бы себя за
проверку кода.

**Следствия.** Утверждение «работает» о правке кода — только после
сборки и сценария; до того — «не проверено». Сборка оригинала в сессии
под Mono — шаг переноса на C++ (D-08); когда она появится, это решение
уточняется новым.

**Проверка.** `python3 tools/check_docs.py`: каталога `.github/workflows/`
нет; обзор: в описании PR есть раздел «Проверки».

**Отклонено.** Сборка на раннере Windows в GitHub Actions — противоречит
E-07 экосистемы и требует отдельного решения автора.

### D-08 — Перенос программы на C++ — первая крупная задача

**Статус.** Принято — поручение автора 13 октября 2026 («запиши первую
крупную задачу в ROADMAP.md: полный перенос программы на C++»). Стек,
платформы и судьба этапов 2–5 — открытые вопросы автору (`TODO.md`).

**Решение.** Программа целиком — все четыре режима, меню и панели,
профили и файлы, история, достижения, темы, звук — переносится на C++.
Это первая крупная задача проекта: в очереди `ROADMAP/ROADMAP.md` она
стоит перед этапами 2–5. Pascal-версия остаётся рабочей программой и
описывается D-02, пока перенос не достигнет её возможностей; после этого
D-02 заменяется новым решением о платформе C++, а оригинал становится
эталоном, который не правится.

**Почему.** Направление задал автор; его доводы в журнал не записаны —
дополнить. Наблюдения аудита о том, что перенос меняет: проверка кода
командой в сессии (C++ собирается на Linux — так у TrueJointTileMaker,
`TrueJointTileMaker:docs/porting.md`); часы кадра без зависимости от
версии PascalABC.NET (AUD-01); ввод в одном потоке (AUD-02, AUD-03,
AUD-16).

**Следствия.**

- Находки `AUD-NN` — требования к переносу: дефект оригинала не
  переносится; где перенос ведёт себя иначе, чем оригинал, отличие
  записывается со ссылкой на находку. Баланс режимов, пороги рекордов и
  комбо (AUD-04, AUD-08, AUD-10, AUD-26) переносятся как есть, пока
  автор не решит иначе.
- Этапы 2–5 написаны аудитом для Pascal-версии до этого поручения. Что
  из них делать в Pascal-коде до переноса — решает автор; до ответа
  Pascal-код правится только по отдельному поручению. Сборка и прогон
  оригинала как эталона — часть переноса, а не правка.
- Стек — первый шаг задачи и отдельные решения: язык и стандарт,
  графика и ввод, платформы, сборка, место оригинала, совместимость
  файлов профиля. Рекомендация сессии — путь TrueJointTileMaker: C++ и
  SDL2, CMake, оригинал в `pascal/`, сверка снимков окон с эталоном под
  Mono и Xvfb. Это рекомендация, не решение.
- Раскладка корня меняется (исходники C++, файлы сборки, `pascal/`) —
  тем же новым решением и правкой `ROOT_ALLOW` в `tools/check_docs.py`.

**Проверка.** Обзор при каждом PR: пока задача открыта, она — первая
открытая в `ROADMAP/ROADMAP.md`; правка Pascal-кода в PR ссылается на
поручение автора. Готовность переноса — критерий выхода задачи в
`ROADMAP/ROADMAP.md`.

**Отклонено.** Довести Pascal-версию по этапам 2–5 до переноса
(рекомендация аудита 13 октября 2026) — автор поставил перенос первым.
