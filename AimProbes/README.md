# Замерщики ввода: выбор библиотеки по точности замера реакции

Поручение автора 15 октября 2026: точность замера реакции нужна
максимальная, выбор SDL3 (D-10, D-18) можно пересмотреть. Прежде чем
переносить игру, на машине автора меряется, как быстро и как точно разные
библиотеки сообщают программе о клике. По итогам — решение о библиотеке,
затем перенос на неё.

Каждый замерщик — минимальная программа: окно 800×600, круги под клик и
фоновый журнал рядом с программой. Код — `tools/lib_probes/`.

## 1. Что в архиве

| файл | библиотека | время клика у библиотеки (по исходнику) | когда программа узнаёт о клике |
|---|---|---|---|
| `AimProbe_SDL3.exe` | SDL 3.4.18 | `msg.time` сообщения Windows, мс (`WIN_GetEventTimestamp`) | при опросе событий |
| `AimProbe_SDL3_raw.exe` | SDL 3.4.18, относительный режим мыши | метка в потоке сырого ввода SDL при получении пакета | при опросе событий; курсор рисует программа |
| `AimProbe_SDL2.exe` | SDL 2.32.10 | `SDL_GetTicks` в момент опроса, мс | при опросе событий |
| `AimProbe_GLFW.exe` | GLFW 3.5.1 | нет | в колбэке из `glfwPollEvents` |
| `AimProbe_raylib.exe` | raylib 6.0 | нет | раз в кадр: состояние кнопки после смены кадра; «показ кадра» — весь `EndDrawing` |
| `AimProbe_SFML.exe` | SFML 3.1.0, окно и OpenGL | нет | при опросе событий |
| `AimProbe_Allegro.exe` | Allegro 5.2.11.3 | `al_get_time` (QueryPerformanceCounter) в отдельном потоке окна, когда он разбирает сообщение: поток спит ~1 мс перед каждым сообщением и берёт по одному | при опросе очереди событий |
| `AimProbe_WinAPI.exe` | без библиотеки: Win32 и GDI | `msg.time` (`GetMessageTime`), мс — тот же счётчик, что у SDL3, пересчитанный в шкалу QueryPerformanceCounter так же, как в SDL3 | в оконной процедуре |

Название библиотеки — в имени файла и в свойствах EXE («Подробно» →
«Описание файла»).

## 2. Как запустить — у автора на Windows

1. Скачать сборку: ветка `win_debug_builds` на GitHub → «Code» →
   «Download ZIP» (D-23), в архиве — папка `AimProbes`. Суммы EXE —
   `AimProbes/SHA256SUMS`, из какого коммита собрано — `BUILD.md`.
2. До распаковки: «Свойства» скачанного ZIP → отметить «Разблокировать» →
   «ОК». Тогда Windows не спрашивает про каждый EXE без цифровой подписи.
   Если всё же покажет «Система Windows защитила ваш компьютер» —
   «Подробнее» → «Выполнить в любом случае». На Windows 11 с включённым
   «Интеллектуальным управлением приложениями» (Smart App Control) EXE без
   подписи не запускаются совсем — его придётся выключить.
3. «Извлечь всё» в папку, куда можно писать (например,
   «Документы\AimProbes»), — не в Program Files и не запускать EXE прямо
   из ZIP: тогда журналы окажутся во временной папке.
4. Запустить один EXE. **Пока жёлтая полоса вверху не дойдёт до конца —
   около 15 секунд — мышь не трогать и окно не переключать:** 3 секунды
   ожидания, затем самопроверка — программа сама ставит курсор в левый
   нижний угол окна и 100 раз «кликает» основной кнопкой. Если сдвинуть
   мышь или уйти в другое окно, самопроверка останавливается: полоса
   становится красной, заголовок пишет «САМОПРОВЕРКА НЕ ПРОШЛА» и почему.
   Тогда Esc и запустить заново.
5. Синяя полоса — серия: 30 кругов появляются по одному в случайный момент
   и в случайном месте. Кликать по каждому как можно быстрее. Заголовок
   окна показывает номер цели и последнюю реакцию.
6. Заголовок «готово: журнал в …» — нажать Esc. В заголовке — папка, где
   лежат журналы.
7. Повторить для каждого EXE в одинаковых условиях: та же мышь, без других
   тяжёлых программ, ноутбук — от сети.
8. Прислать все журналы — пары файлов `<библиотека>_<дата>_<время>.log` и
   `.csv`, например `SDL3_20261015_130634.log` и `SDL3_20261015_130634.csv`.
   Файлы не открывать и не сохранять в Excel: он перепишет таблицу.

## 3. Что пишет журнал

Запись фоновая: строки копятся в памяти и раз в 200 мс уходят на диск из
своего потока, поэтому не задерживают кадр, а при падении программы
теряется не больше 200 мс.

- `<библиотека>_<дата>_<время>.log` — сведения о системе (Windows,
  процессор, частота экрана, разрешение таймера и `Sleep(1)` в процессе,
  шаг `GetTickCount`, масштаб, положение окна, переставлены ли кнопки
  мыши), зерно случайности, ход замера раз в 10 секунд, итоги
  самопроверки и серии, причина выхода.
- `<библиотека>_<дата>_<время>.csv` — строка на каждый клик. `kind`:
  `selftest` — клик самопроверки, `trial` — клик по цели, `anticipation` —
  кнопка нажата раньше показа кадра с целью (упреждение, в реакцию не
  входит), `early` — клик до появления цели, `timeout` — цель без клика.
  Время — мс от запуска программы по QueryPerformanceCounter; `lib_native`
  — метка библиотеки в её собственных единицах, для пересчёта.

## 4. Что сравнивается

Все числа — в одной шкале: QueryPerformanceCounter.

- **Эталон — сырой ввод.** Свой поток высшего приоритета получает пакет
  мыши (`WM_INPUT`) и сразу ставит метку: раньше программа без драйвера о
  клике не узнаёт. Задержку самой мыши и USB (шаг опроса 1–8 мс) не видит
  никакая программа — она одинакова для всех библиотек.
- **Самопроверка.** 100 кликов основной кнопкой (у левши — правой)
  `SendInput` в известный момент. Момент выбирается по
  QueryPerformanceCounter, а не по `Sleep`, поэтому он случаен и
  относительно кадра, и относительно тика системного таймера, по которому
  шагает `msg.time`, — как у настоящего игрока. Кнопка держится 40–70 мс,
  как у человека: библиотека, которая видит кнопку только раз в кадр
  (raylib), нажатие не теряет. Каждой инъекции достаётся только то, что
  пришло до следующей: потерянный клик считается потерянным («потеряно» в
  итоге) и не сдвигает следующие пары. Перед каждым кликом проверяется, что
  окно впереди, курсор на месте и точка клика принадлежит окну программы,
  а не панели задач; окно в начале сдвигается целиком в рабочую область
  экрана. По самопроверке:
  - «получено программой − SendInput» — через сколько библиотека отдаёт
    клик программе;
  - «метка библиотеки − SendInput» — точность её метки времени. Для замера
    реакции важен **разброс** (откл., от p5 до p95): постоянный сдвиг
    вычитается, разброс — нет.
- **Серия.** Реакция по эталону, по метке библиотеки и по моменту
  получения; расхождения между ними на живых кликах.
- **Кадры.** Интервал между показами и время вызова показа.
- **Одинаковые условия.** Все замерщики включают таймер 1 мс
  (`timeBeginPeriod`): с Windows 10 2004 разрешение таймера у каждого
  процесса своё, а часть библиотек его не повышает.

Лучшая библиотека — с наименьшим разбросом того времени, по которому игра
будет считать реакцию (D-12): метки библиотеки, если она есть, иначе
момента получения. Задержка получения важна и сама по себе: по ней игра
отвечает на клик.

## 5. Чего замер не видит

- Время от показа кадра до изображения на мониторе (D-12) — оно зависит от
  способа вывода, а не от разбора ввода; здесь сравнивается ввод.
- Искусственный клик `SendInput` проходит путь от системной очереди ввода,
  без USB и драйвера мыши; это одинаково для всех библиотек.
- В `AimProbe_SDL3_raw.exe` своего потока сырого ввода нет: сырой ввод
  мыши в процессе получает кто-то один, здесь — SDL. Сравнение — по
  самопроверке.
- Под Wine и в виртуальной машине числа непоказательны.

## 6. Сборка

Кросс-сборка под Windows в сессии — `tools/lib_probes/build.sh` (llvm-mingw
20261006, D-17); итог — архив `build/lib_probes/AimProbes-win64.zip`.
Устройство — `tools/lib_probes/CMakeLists.txt`: одна библиотека — один
каталог сборки, всё статически, свой код — с предупреждениями как
ошибками. Выкладка в ветку `win_debug_builds` (D-23) —
`tools/lib_probes/publish.sh`: только из закоммиченного кода, с
`SHA256SUMS` и `BUILD.md`.
